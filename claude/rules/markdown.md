# Markdown Rules

Markdown formatting standards for all documentation in enterprise projects.

These rules apply to every `.md` and `.mdx` file in the repository. CI and pre-commit
hooks run `markdownlint-cli2` against the project's `.markdownlint.jsonc` configuration
on every push. All findings must be resolved before merge.

---

## Tooling

`markdownlint-cli2` is the required linter. Configuration lives in `.markdownlint.jsonc`
at the repository root. Do not use `.markdownlint.json` or `.markdownlint.yaml`; the
JSONC variant supports comments and is the project standard.

Run the linter locally before committing:

```sh
markdownlint-cli2 "**/*.md"
```

The pre-commit hook runs the same command. Install hooks with `pre-commit install` once
per clone.

---

## Formatting Rules

### Indentation

Use spaces for indentation in all Markdown files. Hard tabs are forbidden except inside
fenced code blocks where the target language requires them (for example, Makefile recipe
lines). The `markdownlint.jsonc` config permits tabs inside code blocks for this reason.

### Headings

- Use ATX-style headings (`#`, `##`, `###`), never Setext-style (`===`, `---` underlines).
- Every file contains exactly one `#` (H1) heading, placed at the top of the document.
- Heading levels must be sequential. Do not skip from `##` to `####`.
- Leave one blank line before a heading and one blank line after it.

### Lists

- Unordered lists use `-` as the list marker. Do not use `*` or `+`.
- Ordered lists use sequential integers starting at `1`: `1.`, `2.`, `3.`.
  Do not use `1.` for every item.
- Nest list items with consistent indentation (two spaces per level).

### Code Blocks

- Use fenced code blocks with triple backticks. Do not use indented code blocks.
- Always specify a language identifier for syntax highlighting.

```python
def greet(name: str) -> str:
    """Return a greeting string."""
    return f"Hello, {name}"
```

- Makefile code blocks use real tabs for recipe lines; this is correct and expected:

```makefile
test:
	uv run pytest
```

The linter config explicitly allows tabs inside code blocks to accommodate this.

### Tables

- All tables must use leading and trailing pipe characters on every row.
- Align separator rows with dashes only; do not pad with spaces for visual alignment.

```markdown
| Column A | Column B |
| -------- | -------- |
| value    | value    |
```

### Whitespace and Line Endings

- No trailing whitespace on any line.
- Files must end with exactly one newline character.
- Use Unix line endings (`LF`). Do not commit files with `CRLF` line endings.

### Line Length

Wrap prose lines at approximately 88 characters. This matches the Python line length
convention used across the project and keeps diffs readable. Code blocks, tables, and
URLs are exempt from the line-length limit.

## File Naming

Name standalone Markdown documents in `kebab-case.md`. Examples:

- `getting-started.md`
- `api-reference.md`
- `architecture-decision-record.md`

Files generated by tooling (for example, `CHANGELOG.md`, `README.md`, `LICENSE`) follow
their conventional all-caps names.

---

## Links and References

- Prefer reference-style links for URLs that appear more than once in a document.
- Use relative paths for links between files in the same repository.
- Bare URLs must be wrapped in angle brackets: `<https://example.com>`.
- Do not use empty link text.

---

## Code Review Gate — Markdown

Before marking any documentation change as complete, verify:

- [ ] `markdownlint-cli2` passes with no errors against `.markdownlint.jsonc`.
- [ ] Exactly one `#` heading per file.
- [ ] Heading levels are sequential with no skipped levels.
- [ ] Blank lines present before and after every heading.
- [ ] All fenced code blocks carry a language identifier.
- [ ] Unordered lists use `-`; ordered lists use sequential numbers.
- [ ] Tables have leading and trailing pipes on every row.
- [ ] No trailing whitespace on any line.
- [ ] File ends with exactly one newline.
- [ ] Prose lines wrap at approximately 88 characters.
- [ ] File is named in `kebab-case.md` (unless a conventional name applies).
